# CI System Mapping

| Concept | GitHub Actions | Azure DevOps | GitLab CI | Jenkins |
|---|---|---|---|---|
| Trigger | `on: push`, `pull_request`, `workflow_dispatch` | `trigger:` for pushes; `pr:` for pull requests | Runs on **every push by default** (no trigger block needed); `workflow: rules` narrows which pipelines are created; job-level `rules:` controls job execution | `triggers {}` in Declarative Pipeline, or webhook |
| Job | `jobs:` → job ID → `steps:` using `run:` or `uses:` | `stages:` → `jobs:` → `steps:` | Top-level job name; `stage:` assigns stage; `script:` runs commands | `pipeline { stages { stage('Build') { steps { sh '...' } } } }` |
| Runner/agent | `runs-on: ubuntu-latest`; optional `container: { image: ... }` | `pool: vmImage: ubuntu-latest`; optional `container:` | Runner selected by `tags:`; `image:` specifies job container | `agent any` or `agent { docker { image '...' } }` |
| Artifact | `actions/upload-artifact` / `actions/download-artifact` | `publish:` or `PublishPipelineArtifact@1`; download with `download:` or download task | `artifacts: paths: [...]`; availability depends on stage and dependency settings | `archiveArtifacts artifacts: '...'`; `stash` / `unstash` between stages |
| Cache | `actions/cache` with `key:` and `path:`; `setup-python` supports `cache: pip` | `Cache@2` with `key:` and `path:` | `cache: key: ...; paths: [...]` | Reused workspace or caching plugin; no equivalent built-in general-purpose cache |
| Secret | `${{ secrets.NAME }}`; repository, organization or environment secrets; environment rules can gate access | Secret variables or variable groups; can link to Azure Key Vault; reference with `$(NAME)`; **secrets are not passed to scripts automatically** — map each one into the step's `env:` | CI/CD variables such as `$NAME`; masked and/or protected; protected variables are restricted to eligible protected refs | Credentials store; `withCredentials([...])` or `environment { X = credentials('id') }`; masking does not prevent malicious pipeline code from exposing credentials |
| Matrix | `strategy: matrix: python: ['3.10', '3.11']`; reference with `${{ matrix.python }}` | `strategy: matrix:` with named configurations and variables | `parallel: matrix:` on a job | Declarative `matrix { axes { axis { name 'PY'; values '3.10', '3.11' } } }` |
| Condition | `if:`, e.g. `if: always()` or a PR condition | `condition:`, e.g. `condition: always()` or `eq(variables['Build.Reason'], 'PullRequest')` | `rules: - if:` and `when:`, e.g. `when: always` | `when { branch 'master' }`; `post { always { ... } }` |
| Environment/approval | `environment: production`; required reviewers and protection rules configured in repository settings | `deployment:` job with `environment: production`; approvals and checks configured on the Environment | `environment: name: production`; protected environments and deployment approvals configured in settings, subject to GitLab tier; `when: manual` alone is not a protected approval | `input message: 'Deploy?', submitter: 'ken'` in the Jenkinsfile |
 
**Security takeaway:** Keep production deployment approvals in protected settings outside changeable pipeline code where possible, and enforce permissions so a pull request cannot remove or bypass the approval requirement.
